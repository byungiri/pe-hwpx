## 3. 결론 및 2단계 반영 사항

- 본 도구가 저장한 HWPX는 한글에서 오류 없이 열리고 PDF로 변환된다.
- 한글은 문단의 줄 배치 캐시(hp:linesegarray)가 있으면 이를 우선 사용한다. 텍스트 길이가 바뀌면 캐시와 실제 내용이 어긋나 글자가 압축·중첩된다.
- 캐시를 제거하면 한글이 열 때 줄 배치를 다시 계산하며, 셀 높이도 내용에 맞게 늘어난다.
- **2단계 채움(fill) 규칙: 텍스트를 바꾼 문단은 hp:linesegarray 를 제거한다.** 변경 범위 diff 에서는 이를 해당 셀 내부 변경으로 집계한다.
- 한글 자동화 스크립트(.ps1)에 한글 경로 문자열을 넣을 때는 UTF-8(BOM) 으로 저장해야 한다(4단계 렌더 도구 작성 시 반영).

## 4. 누름틀·자리표시자 시험

한글 자동화(CreateField, PutFieldText)로 본문·표 안에 누름틀 3건, 자리표시자 3건을 넣은 시험 양식(s7)을 작성해 시험했다.

| 항목 | 놓인 곳 | 상태 | scan | locate |
| --- | --- | --- | --- | --- |
| field:성명 | 표 셀 (s0/tbl[0]/r[6]/c[0]) | 미입력 | 검출, 위치 일치 | 성공, '(미입력)' |
| field:소속 | 본문 (s0/p[1]) | 값 입력 | 검출, 값 '기술법인 진성' | 성공, 값 일치 |
| field:직위 | 새 표 셀 (s0/tbl[1]/r[0]/c[1]) | 미입력 | 검출, 위치 일치 | 성공 |
| {{주소}}, {{발급일}} | 본문 문단 | — | 검출 | 성공 |
| {{연락처}} | 표 셀 (s0/tbl[1]/r[1]/c[1]) | — | 검출 | 성공 |

- 누름틀 위치는 정규식만으로 원본 XML 을 따로 조사한 결과와 일치함을 교차 확인했다.
- 한글은 누름틀이 미입력(dirty=0)일 때 안내문을 내용 자리에 저장한다. 이를 값으로 오인하지 않도록 dirty 속성으로 구분하도록 보정했다(0.1.0 내 수정).
- s7 은 관문 시험(왕복·재직렬화·셀 수정 검출)도 모두 통과했다.

## 6. 운영상 확인 사항

- 한글 자동화에서 보안 모듈 등록(RegisterModule)이 실패하면, **새 파일로 저장할 때** 한글이 '파일 접근 허용' 확인 창을 띄워 자동화가 멈춘다. 기존 파일을 열어 저장하는 경우에는 확인 창이 나타나지 않았다. 4단계 렌더 도구는 '기존 파일 사본 열기 → 저장' 방식을 사용한다.
- PowerShell 스크립트에서 함수 이름 R 은 기본 별칭(Invoke-History)과 충돌한다.

## 7. 스킬 호출 시험 (claude.ai)

- 사용자가 v0.1 을 업로드한 뒤 재직증명서 양식(첨부)에 "이 양식 분석해 줘"라고 요청 → 스킬이 자동 호출되어 읽기 전용 스킬 폴더에서 scan 정상 실행, 입력 칸 8건 제시. **통과**
- 같은 시험에서 병합 셀 안의 '용 도 :' 문단과 발급일 날짜 문단이 후보에서 빠지는 한계를 발견 → 0.2.0 에서 문단 항목·날짜 후보 검출 추가.

## 12. 이미지 배치 (0.4.0)

대상: 공공기관 기술자문위원회 개인정보 수집·이용 동의서. 체크 이미지(□ 동의함), 직인(인 또는 성명).
한글 COM 자동화로 PDF 변환 후 픽셀 분석으로 이미지 중심과 기준 문구 중심의 차이를 측정.

| 방식 | 직인 오차 (가로, 세로) | 체크 오차 (가로, 세로) | 쪽 수 |
| --- | --- | --- | --- |
| 측정(PDF 실측, 용지 기준) | (-0.1, -0.4) mm | (0.2, 0.1) mm | 1쪽 유지 |
| 추정(문단 기준, 위 문단 앵커) | (-0.1, -1.4) mm | (7.2, -1.0) mm | 1쪽 유지 |

시행착오와 조치
- 앵커용으로 새 줄(빈 런)을 추가하자 표 뒤에 줄이 생겨 2쪽으로 넘어감 → 그림을 기존 런 맨 앞에 넣도록 변경.
- 한글은 문단 기준 개체의 음수 세로 위치를 0 으로 제한함(위로 올릴 수 없음) → 충분히 위쪽 문단에 앵커하고 아래로 내려 배치.
- 본문 흐름 제한 해제(flowWithText=0)는 문단 기준 개체를 쪽 위쪽으로 보내 사용하지 않음(용지 기준 배치에만 사용).
- 중첩 표 안 문단의 가로 기준점이 추정과 달라 7mm 오차 → 추정 방식 한계로 문서화, 측정 방식 권장.

자동 시험 (tests/gate4.py, 시험용 단색 PNG): 9종 문서 모두 그림 1개 추가, 구조 오류 0, 지정 위치 밖 변경 0, 결과물 재저장 바이트 동일.
1·2·3차 관문 회귀 시험 통과.

운영 확인: 한글 '파일 접근 허용' 확인 창은 상황에 따라 나타났다 사라짐(같은 파일이 이후에는 정상 변환). 자동화는 대기 시간 후 해당 프로세스만 종료하는 방식으로 운용.

## 13. 0.4.1: 직인 14mm, 이미지 돌려쓰기, 손 느낌 체크

요청: 직인 크기 14mm, 한 문서 안에서 직인·서명·체크 이미지를 돌려 사용, 체크 위치를 손으로 한 것처럼 조금씩 다르게.

| 항목 | 방법 | 결과 (한글 PDF 288dpi 분석) |
| --- | --- | --- |
| 직인 크기 | 여백 자르기 후 인영 폭 = 14mm | 3종 모두 13.6~13.9mm |
| 직인 위치 | PDF 실측 배치 + 흔들림 ±0.5mm | 중심 오차 0.3mm 이내(흔들림 포함) |
| 돌려쓰기 | 시험 문서에 직인 3곳·체크 3곳·서명 1곳 배치 | 직인 3종, 체크 3종이 각각 한 번씩 사용됨 |
| 손 느낌 체크 | 위치 ±1.2mm, 각도 ±10°, 크기 ±10% | 상자마다 기울기·위치가 다르게 표시 |
| 사진형 직인 2종 | 회색 배경 자동 투명화 | 뒤 글자가 비침, 잉크 불투명도 251~254/255 |

시행착오와 조치
- 사진형 직인은 이미지 안 여백 때문에 14mm 지정 시 11.4mm 로 찍힘 → 투명 여백 자르기 추가.
- 배경 명암이 고르지 않은 사진에서 배경 일부가 남아 12.3mm 로 작게 찍힘 → 테두리 색 차이 기반 적응형 투명 경계.
- 인영이 이미지 가장자리에 닿는 사진은 경계가 과도하게 높아져 인영이 흐려짐(불투명도 79) → 상위 10% 제외·상한 70 적용 후 251.

자동 시험: gate4 에 '역할 이미지 돌려쓰기(순환·시드 재현·범위)', '배경 투명화·여백 자르기' 단위 시험 추가. 1~4차 관문 전부 통과.
